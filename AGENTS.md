# Semgrep Network Broker agent guide

This is the authoritative repository-wide agent guide. `CLAUDE.md` imports it.
The broker runs in customer networks, establishes a WireGuard tunnel, and proxies
Semgrep requests to configured private services. Read [README.md](README.md) for
operator configuration and supported integrations.

## Layout

- `cmd/`: Cobra commands, configuration entry points, relay, and key utilities.
- `pkg/`: Allowlist/configuration logic, inbound proxy, HTTP client, WireGuard,
  relay, heartbeat, token handling, logging, and metrics.
- `broker.proto`: Protocol source; generated Go code lives in `protos/`.
- `pkg/*_test.go`: Unit tests for configuration, allowlists, and redaction.
- `it/e2e_test.go`: End-to-end coverage using local servers and network sockets.
- `tools/readme-url-populator/`: Generates README allowlist sections from config logic.
- `examples/` and `kubernetes.yaml`: Deployment/configuration examples.

## Build and validation

Use the Go version declared in `go.mod` and the Buf version in `.buf-version`.
Run from the repo root:

```bash
make build
make test
pre-commit run --files <changed-files>
```

`make build` downloads dependencies, regenerates protobufs, and writes
`bin/semgrep-network-broker`. `make test` includes that build and runs
`go test -v ./...`, including `it/`. The end-to-end tests need local network sockets.
For focused package checks during iteration, use `go test ./pkg` or a suitable
`-run` filter; use `make test` for the complete code-change check.

- For protocol changes, edit `broker.proto`, run `make protos`, and commit generated
  output. `buf.gen.yaml` pins the remote generator, so generation needs registry
  access. Do not hand-edit `protos/`.
- CI separately checks generated output and protobuf backward compatibility against
  `develop`; see [.github/workflows/test.yml](.github/workflows/test.yml).
- `make docker` builds the local image with version/revision/build-time metadata.
- Root hooks run Go formatting, file hygiene, protobuf generation for `.proto`
  changes, and the always-run README URL populator. Review generated README changes.
  Do not hand-edit text inside `BeginAutogeneratedAllowList`/`EndAutogeneratedAllowList`
  markers to change the documented allowlist.
- Documentation-only edits need formatting, local-link, and reference checks.

## Configuration and compatibility

- Preserve allowlist enforcement and the existing `allowCodeAccess` opt-in boundaries
  for provider endpoints. Cover both permitted and denied requests when changing
  patterns or provider-generated rules.
- Keep HTTP methods, URL matching, configured trust roots, and TLS options aligned
  with their documented behavior. Check `pkg/allowlist_test.go` and `pkg/config_test.go`
  when changing these interfaces.
- Preserve sensitive-header and configuration redaction; add regression coverage in
  `pkg/logger_test.go` or `pkg/config_test.go` when adding sensitive fields. Never
  include real customer private keys or credentials in examples, fixtures, or logs.
- Preserve existing customer configuration compatibility. The README's instruction
  not to alter provisioned WireGuard settings applies to operator configuration;
  changes to tunnel behavior need corresponding tests and documentation.
- Use the existing Logrus logging and testify testing patterns in this repository.
  Check surrounding code rather than importing conventions from another Semgrep repo.

## Releases

Use `develop` as the integration branch. The publish workflow builds images for
GHCR on pushes to `develop`, published releases, and manual dispatch; see
[.github/workflows/publish.yml](.github/workflows/publish.yml) for tags and build
settings. Publishing is separate from local validation. Coordinate protocol changes
with the gateway side in the sibling `semgrep-private-link` repository.
